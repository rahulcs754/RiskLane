GitHub Action · Rule-based · Free and open source

Review the risky PRs first.

AI tools make PRs faster than seniors can review them. RiskLane reads each PR's diff, gives it a risk score with reasons, and sends only the risky ones to senior reviewers.

Add to your repo View on GitHub

Three lanes

Low (0-29)

Small change, safe area, tests included. One quick review.

Medium (30-59)

Bigger change or a sensitive area. Normal, careful review.

High (60+)

Auth, payments, migrations, infra, big diff, no tests. Senior review, auto-requested.

What it checks

Sensitive areas

Auth, payments, DB migrations, infra, CI pipelines, app config. Add your own paths.

Size

Lines and files changed. Lockfiles, docs and generated files do not count.

Missing tests

Code changed but no test file changed.

Risky code

eval, raw HTML, shell exec, SQL from strings, empty catch, TLS off, lint disabled.

Dependencies

Manifest or lockfile changes.

Hotspots

Files changed 10+ times in 90 days break more often.

Quick start

  1. Add .github/workflows/risklane.yml: 
    name: RiskLane
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
permissions:
  contents: read
  pull-requests: write
  issues: write
jobs:
  risk:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: rahulcs754/risklane@main
  2. Optional: add risklane.json to send high-risk PRs to seniors: 
    { "reviewers": { "high": ["your-senior-dev", "your-org/seniors"] } }
  3. Open a PR. You get one comment, a risk:* label, and reviewers on high-risk PRs.

Why rules, not AI?

Every point has a reason you can read. It runs in under a second, costs nothing, and your code never leaves your CI. Tune the weights in risklane.json until the lanes match how your team thinks about risk.
